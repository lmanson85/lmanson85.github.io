Secure Network Design & System Hardening

A defense-in-depth security project that progressed from identifying common small-business threats and designing a secure network architecture to implementing and validating security controls across Windows Server 2022 and a segmented Cisco network.

Windows Server 2022 Group Policy Windows Firewall Access Control VLANs ACLs Cisco Packet Tracer Network Segmentation Patch Management

Project Overview

This project combined two related cybersecurity assignments. The first focused on designing a secure network for a small-business environment after identifying likely threats and weaknesses. The second moved from design into implementation by applying security controls to Windows Server 2022 and a Cisco network environment and then validating that those controls behaved as intended.

The Security Challenge

The environment presented several common security problems that could expose systems, users, and business data to unauthorized access or disruption.

RISK 01

Weak Authentication

Weak password practices increase the likelihood of compromised accounts and unauthorized access.

RISK 02

Unauthorized Access

Users required different levels of access to internal files and resources based on their role.

RISK 03

Flat Network Exposure

Without segmentation, systems belonging to different business functions could communicate more freely than necessary.

RISK 04

Unpatched & Exposed Systems

Missing updates and unnecessary network access can increase the attack surface and expose known vulnerabilities.

Secure Network Architecture

Before implementing controls, I designed a defense-in-depth network architecture intended to reduce exposure, improve visibility, secure remote access, and limit unnecessary communication between systems.

Architecture Components

  • IDPS-enabled perimeter device
  • Firewall
  • Managed switch with port security
  • Wireless access point
  • VPN server
  • Centralized logging server
  • NAS server
  • Web server
  • Email server
  • Antivirus-protected endpoints
  • Restricted remote access
  • Network segmentation

Windows Server Hardening

Windows Server 2022 was hardened using Group Policy to establish stronger authentication requirements and reduce the risk associated with weak or repeatedly guessed passwords.

Password & Account Lockout Controls

12 Characters Minimum password length
Password Complexity Uppercase, lowercase and special-character requirements
6 Months Password expiration period
24 Passwords Password history enforced
5 Attempts Invalid attempts before lockout
15 Minutes Account lockout duration
Validation Evidence: The project documentation contains screenshots from Windows Local Group Policy Editor showing the configured password and account-lockout policies.

Role-Based File Access

File and folder permissions were configured so that access to sensitive information depended on the user's assigned permissions rather than simply having access to the shared location.

USER TEST 01

Restricted User

The user could reach the shared folder but was prevented from accessing protected information that exceeded the user's assigned permissions.

USER TEST 02

Authorized User

A user with the appropriate permissions was able to access both the shared location and the protected file.

Validation Evidence: Screenshots in the original project demonstrate both successful authorized access and denied access for the restricted user.

Firewall & Patch Management

CONTROL 01

Windows Defender Firewall

Inbound firewall rules were reviewed and configured to restrict network access and allow required services while reducing unnecessary exposure.

CONTROL 02

System Updates

Windows Update was used to identify and install available updates, demonstrating the role of patch management in reducing exposure to known vulnerabilities.

Patch Management Approach

The supporting secure-network design also documented a patch lifecycle that included maintaining an asset inventory, scheduling deployments, testing updates in a controlled environment, creating backups before deployment, and documenting and reviewing completed updates.

Network Segmentation

The network was segmented into separate VLANs so that business groups could be logically separated rather than operating within one unrestricted network.

Admin VLAN

Administrative systems were placed within their own logical network segment.

HR VLAN

Human Resources systems were separated from other organizational traffic.

IT VLAN

IT resources were assigned to a dedicated segment to support controlled network communication.

Guest VLAN

Guest traffic was logically isolated from internal business resources.

ACL Enforcement

Access Control Lists were implemented in the Cisco environment to control traffic between network segments. This added an enforcement layer on top of VLAN segmentation by defining which cross-network communication was permitted.

Defense-in-Depth

VLANs provided logical separation while ACLs controlled communication between those segments. Together, these controls reduced unnecessary lateral access and supported the principle of least privilege at the network level.

Security Validation

The final step was not simply configuring the controls—it was testing whether they actually produced the intended security behavior.

VALIDATION 01

Permitted Communication

Ping testing demonstrated successful communication where the network policy allowed traffic.

VALIDATION 02

Blocked Communication

Cross-segment testing produced timeouts where ACL rules were intended to prevent communication, validating network isolation.

VALIDATION 03

File Permissions

User testing confirmed that protected files could be accessed by authorized users while restricted users were denied.

VALIDATION 04

Security Configuration

Group Policy, firewall settings, updates, VLAN configuration, and ACL implementation were documented with screenshots and configuration evidence.

Additional Security Testing Strategy

During the architecture phase, I also documented additional methods that could be used to evaluate the security of the environment. These were proposed testing approaches rather than tools implemented as part of the final build.

Wireshark

Inspect VPN traffic to verify that communications are encrypted.

Burp Suite Intruder

Evaluate password and authentication resilience through controlled testing.

Qualys

Perform vulnerability and patch scanning to identify exposed systems.

Metasploit

Conduct controlled penetration testing against identified weaknesses.
